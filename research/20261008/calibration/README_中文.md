# 本地评分会错杀多少好候选：T2/T3证据包

日期：2026-10-08。只复核既有记录；没有新训练、读取隐藏目标或新增提交。

## 先看结论

目前没有“本地达到X，服务器一定好”的可靠门槛，也不能给本地分统一加一个修正值。确实发现了会漏掉服务器好结果的本地筛选规则，但还不能估计全部未提交候选的错杀率。

- T3：固定供体复核中，v85方法在本地五项指标、全部六个重叠分层都优于v84方法；服务器却是v84=49.55、v85=47.45。若只选本地占优者，会损失2.10服务器分，并漏掉v84相对当时现役47.93的+1.62提升。两者实际上都提交了，所以这是对假设筛选规则的反事实检验，不是声称v84曾被丢弃。来源WT载体和目标hurdle载体不同，不能把2.10直接加回本地分。
- T2心脏外推：v22本地相对综合分−3.18，服务器反而比历史基线高0.21；v11本地只有+0.0297，服务器高0.11。在16个已提交的历史备选中，“本地>1”会放行5个，却漏掉这两个超过历史基线的结果。这个分母不含未知服务器结果的未提交拒绝者，也不是整体错杀率。v22相对当时更高现役只高0.10，属于平局边界。
- T2另一时间留出协议：v30本地误差比0.92868，未达“≤0.90”进步目标，服务器仍获51.12并晋级。说明未达理想改善幅度不等于不能赢；开发修改100%行、最终只修改32%行，因此是方法级证据，不是同一预测文件的校准配对。
- 高本地分也不保证好：T2本地+3.913对应服务器50.09，低于历史基线0.44；T3 v54本地WT组均值误差改善约2.84%，服务器却比对应父版本低0.18。
- 最新T3 v88相对v87：源侧+0.3253、Mab诊断+0.2270、服务器+0.27，同向且幅度接近；只有一组候选—父版本，不能据此保证下一次。

## 正确读数

T2旧综合分、T2时间留出误差比、T3来源原始指标、Mab自定义校准分和服务器skill总分各自保留单位与协议，禁止混成一个回归分差。六个来源分层、多个种子、同族变体都不是独立的服务器试验。

建议本地分优先用于“先试谁”。文件合法性、数据泄漏、不可复现等硬问题另行处理；对于有依据的新机制，不能仅凭跨域代理分低就永久淘汰。在用户批准的预算内，才考虑少量覆盖不同机制的探索，以逐步观察本地拒绝区的真实结果。本包不启动任何新的提交。

## 内容与复现

- t2/REPORT.md：T2各协议的详细结论、来源和限制
- t3/REPORT.md：T3逐项反转、身份与载体差异、最新配对
- INDEPENDENT_REVIEW.md：统计口径与关键例子的独立核对
- 两目录内CSV/JSON：逐条配对、阈值、排名、数据来源SHA256
- analyze.py：使用本包内小型证据快照重算审计统计；原始模型/评分器重跑仍需未打包的大型数据缓存
- provenance/FINAL_MANIFEST_SHA256.json：发布文件完整性清单；原始包和发布转换分别保留哈希

证据完整性优先于漂亮的总体相关性。未评分项保持未知，历史数据缺少原始字节的项保留明确标注。
